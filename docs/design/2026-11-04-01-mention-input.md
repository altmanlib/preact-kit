# 提及输入框与候选列表

## 1. 目标与范围

输入触发字符(如 `@`, `#`)后在输入框旁列出候选, 选中后写入输入框; 其中一种形态让提及显示为整块的标签(chip), 但输入框里的内容始终是纯文本

范围: `Suggest`(附着在原生输入框上的候选列表)与 `MentionInput`(提及显示为 chip 的输入框), 以及它们共用的触发判定与候选列表. 不含候选数据的来源与过滤, 那由使用方决定

## 2. 现状与约束

- 现有弹层(`Dropdown`, `Select`)由按钮触发, 打开后焦点移进菜单; 候选列表要求焦点一直留在输入框, 不能复用
- 本库不依赖 `preact/compat`, 也不引入内部引用它的库(见 `2026-10-31-headless-library-survey.md`)
- 弹层统一基于 Popover API 与 CSS anchor positioning
- 运行时依赖只有 `lucide-preact`; 只有个别组件才用的依赖放可选 peer

## 3. 原则

- 内容是纯文本: 输入框交给使用方的永远是字符串, 不是 HTML 也不是文档结构. 使用方存储, 传输, 校验长度都不必认识编辑器
- 候选由使用方过滤, 选择结果交回使用方: 组件不认识候选从哪里来
- 键盘与输入法优先: 候选打开时的按键不会漏到输入框自己的处理; 输入法组字期间不拦截任何按键

## 4. 方案

### 4.1 两种形态, 共用同一套判定与列表

- `Suggest` 包住一个 `<input>` 或 `<textarea>`: 输入框是使用方的, 选择后组件算出新文本与光标位置交回, 由使用方写入. 适合不需要 chip 的场景
- `MentionInput` 自带输入框, 提及显示为 chip. 适合需要把提及当整体(整块删除, 单独着色)的场景
- 两者共用: 触发判定(纯函数), 按键含义(纯函数), 候选列表. 否决只做一种: 只做 `Suggest` 无法让提及成为整体; 只做 `MentionInput` 会让不需要 chip 的场景白背编辑器依赖

### 4.2 触发判定

- 光标紧跟在触发字符之后, 且触发字符与光标之间没有空白, 才算; 取离光标最近的触发字符
- 触发字符紧跟在某些字符之后不算, 避免 `a@b` 这样的邮箱与 `@@`: 默认是 ASCII 字母, 数字, 下划线与另一个触发字符; 汉字之后算(中文输入常不加空格). 这条规则可由使用方替换
- 触发字符可以有多个, 候选按匹配到的触发字符区分

### 4.3 交互

- 焦点始终留在输入框: 上下键移动高亮(循环), Enter 或 Tab 选择, Esc 关闭. 候选打开时这几个键不会到达输入框自己的处理, 所以 Enter 不会同时提交. 带修饰键的按键不拦截
- 输入法组字期间不拦截任何按键: 组字时的 Enter 是确认候选字, 不是选择提及
- Esc 关闭后, 在同一个触发字符处继续输入不再弹出; 删掉它再输入新的触发字符才重新弹出. 输入框失焦即关闭
- 在候选列表上按下不抢走输入框焦点, 鼠标点选与键盘选择走同一条路径
- 列表是不抢焦点的手动弹层, 定位在输入框下方, 空间不够时翻到上方
- 输入框带 combobox 的无障碍属性(展开状态, 控制的列表, 当前高亮项)

### 4.4 `MentionInput` 的内容契约

- `onChange` 与 `onSubmit` 得到字符串: chip 是它的文字, 换行是 `\n`. 使用方不需要知道 chip 的存在
- 粘贴与拖入只保留文本, 不接受任何标记. 拖入整个忽略
- chip 是原子: 选中, 删除, 光标移动都按一个整体处理(一次退格删除整块)
- Enter 提交, Shift+Enter 换行; 清空不由组件决定, 通过 `handle` 由使用方在合适的时机清空(例如等服务端确认之后)
- chip 的文字取候选的 `insert`(没有时是触发字符加候选名), 后面自动补一个空格. chip 的颜色可由样式变量覆盖
- 提及不带数据: chip 只是文字. 需要让 chip 携带数据(例如被提及者的 id)时要扩展序列化契约, 见 §6

### 4.5 选型: ProseMirror

- `MentionInput` 基于 ProseMirror, 用一个极小的文档结构: 一个段落, 里面是文本, 换行和提及三种内容, 提及是原子节点. 输入法组字, 撤销重做, 光标管理交给它处理, 本库只写文档结构, 序列化, 粘贴为纯文本, Enter 提交与候选按键
- `prosemirror-*` 是纯 JS, 不绑定任何框架, 不经 `preact/compat`
- 依赖放可选 peer, 只有用这个组件的应用才安装: ProseMirror 要求同一棵依赖树里 model, state, view 各只有一份, 放在本库自己的依赖里会与应用自己用到的版本冲突
- 体量(实测, 一个只含 Preact, signals 与该编辑器的验证页, 压缩后): 约 74 KB, 其中约 65 KB 来自 ProseMirror, Preact 与 signals 基线约 8 KB
- 否决:
  - 手写 contenteditable: 输入法组字, 撤销, 粘贴, 光标这几件事自己处理风险大, 体量节省有限
  - Tiptap: 要带整包 `@tiptap/pm`(含表格, 变更集等用不到的包)与定位库, 而本库已有弹层
  - Lexical: React 绑定需要 React, 要自己写适配; 没有已发布的 mention 包, 提及节点也要自己写
  - Slate, Draft.js: 只有 React 绑定, 会引入 `preact/compat`
  - 把提及存成 HTML 或其他标记: 使用方要净化, 长度被标记吃掉, 下游都要认识标记

### 4.6 验证

- 已验证(浏览器): 触发与过滤, 键盘选择与关闭, 鼠标点选, 整块删除, 撤销, Shift+Enter 换行, 提交与清空, 粘贴 HTML 只留文本, 邮箱形式不触发, 全角触发字符, 禁用状态, 明暗两套主题. 使用方在真机上用中文输入法试过验证页, 组字时的 Enter, 光标与选词符合预期
- 未验证: 触屏与手机输入法, 读屏播报, Firefox 与 Safari. 弹层依赖 Popover API 与 CSS anchor positioning, 目前只在 Chromium 上验证过

## 5. 明确不做

- 富文本格式, 多段落, 图片与附件
- 候选数据的来源, 过滤, 分页(使用方负责)
- chip 携带数据(见 §6)

## 6. 开放项

- 提及需要带数据(如被提及者的 id)时, 字符串契约怎么扩展: 在文字里嵌标记, 还是另给一份提及位置与数据. 等使用方有这个需求时再定, 不预先设计
