# 浏览器冒烟测试

## 1. 目标与范围

`bun run ci` 目前只覆盖 `lib/` 的纯逻辑与架构边界, 交互类组件(键盘, 焦点, 弹层, 对话框)全靠手工在浏览器里验证. 目标: 对核心键盘与焦点路径加自动化回归, 在重构与升级 Zag 时能发现行为退化

范围: 展示站里的 `Modal` `Drawer` `Select` `Combobox` `Dropdown` `DatePicker` `TagsInput` `CommandPalette` `Toast` 的核心路径. 不含视觉回归(截图比对), 不含输入法组字与触屏, 不含 Firefox 与 Safari

## 2. 现状与约束

- 本库只在 Chromium 上验证, 没有跨浏览器要求
- 展示站(`bun run dev`)已经是每个组件的真实挂载点, 不需要另建测试页
- 开发机已装 `playwright-cli`, 但仓库内没有任何浏览器依赖; CI 里没有浏览器

## 3. 方案

- 用 `playwright` 的 Chromium 驱动展示站, 测试文件放 `e2e/*.e2e.ts`, 由 `bun test` 之外的独立命令 `bun run e2e` 运行
- 每个组件一个用例文件, 只断言行为: 打开与关闭, 方向键与回车选择, Esc 后焦点回到触发器, 表单值写入, 焦点陷阱. 不断言像素与动画
- `bun run ci` 不包含 e2e(浏览器下载与耗时); 发版脚本 `release` 与 `merge-main` 在 `ci` 之后增加 `e2e`
- 展示站由测试自己启动在随机端口, 结束后关闭

## 4. 备选与否决

- 否决 happy-dom/jsdom 单测: 没有真实布局与焦点管理, Zag 的 popper 定位, 焦点陷阱, 外部点击判定在其中不可靠, 通过了也不能说明浏览器里可用
- 否决只保留手工验证: 重构一次要手测 10 余个组件, 已经出现过一次只有真浏览器才暴露的问题(`CommandPalette` 的 `aria-label` 被覆盖)
- 否决 `playwright test` 测试运行器: 与 `bun test` 并存两套运行器, 断言与夹具风格不一致; 直接在 `bun test` 里用 `playwright` 库驱动浏览器即可

## 5. 明确不做

- 视觉回归, 跨浏览器, 输入法与触屏, 可访问性自动扫描(列入 ROADMAP 待办)

## 6. 开放项

- 新增 devDependency `playwright`(含约 150MB 的 Chromium 下载), 需要确认可以接受
- e2e 是否要进 GitHub 公开仓库的 CI: 本库当前没有 CI 工作流, 暂不加
